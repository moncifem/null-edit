## 1. Main competition (MAIN, pages: /overview, /data, /rules)

- Task: post-train Gemma 4 into an autonomous SWE agent that fixes real Python bugs / feature requests. Submission is `submission.zip` with root `agent.yaml` (Google ADK Agent Config, restricted so no code runs outside sandbox) + prompts, sub_agents, optional PEFT LoRA adapters (`adapters/<name>/adapter_config.json` + `adapter_model.safetensors`), skills (SKILL.md + scripts). (MAIN/overview Evaluation)
- Metric: SWE-Bench-style PASS/FAIL per issue; score = fraction of issues whose submitted patch passes hidden validation tests. 1 submission/day, 2 final submissions, team max 5. (MAIN Evaluation, rules)
- Limits: 12 h to produce patches for all tasks incl. sandbox setup, excluding patch validation; optional per-task limits in `eval_config.yaml`. (MAIN Evaluation)
- Hardware: Kaggle L4x4 (4 x L4, 96 GB GPU total); L4 sessions only for notebooks attached to this competition; internet must be disabled; L4x4 burns GPU quota 2x. (MAIN "Upgraded Accelerators" page)
- Allowed models (all must be the SAME model for every agent/subagent in a submission; LoRA per agent allowed): `gemma-4-31b-it-qat-w4a16-ct`, `gemma-4-12b-it-qat-w4a16-ct`, `gemma-4-e4b-it-qat-w4a16-ct`, `gemma-4-e2b-it-qat-w4a16-ct`. (MAIN "Model Selection, Budget, and Harness Rules")
- Tools exposed to agent: run_command, submit_patch, get_status, read_file, edit_file, write_file, get_code_neighbors, search_similar_code, get_code_subgraph (graph/embedding tools use provided code graphs + 256-d embeddings). (same page)
- Data (MAIN data-description): `tasks.jsonl` with 129 public dev tasks from 4 repos (fastapi/fastapi, Textualize/rich, psf/requests, encode/httpx); fields instance_id, repo, base_commit, problem_statement, hints_text, patch (gold), test_patch, created_at. Also snapshots/<id>.tgz (git repo at base_commit, history stripped), graphs/ (NetworkX AST call/dependency graphs JSON, 256 files), embeddings/ (.npz, float32 length-256 per node, 256 files), wheels/ (124 offline wheels), docker/ (Python 3.13 sandbox image + imp/telnetlib shims), sandbox/setup.py, sample_submission/ (ADK baseline: YAML schema, multi-agent delegation, multi-LoRA routing), HARNESS_README.md (swegemma, adk-submission, adk-eval-core libs, local CLI eval). Language: Python only. Size in MB: NOT VERIFIED (file listing unauthenticated).
- How tasks built: mined commits touching both .py and test files, linked to issues, filtered refactors/docs/LSCs/ambiguous issues; fail-to-pass and pass-to-pass verification; for the test set, a frontier model must pass or be within one test case. ~120 test tasks split evenly public/private; test set from PRIVATE repositories (so differs from the 4 public repos). (MAIN data-description)
- Timeline: start 2026-09-23; paper deadline 2026-11-12 (optional); entry + merger deadline 2026-11-25; final 2026-12-02 23:59 UTC. (MAIN Timeline)
- Prizes: rules say total $65,000 (37k/18k/10k); API metadata says reward "75,000 Usd"; plus a separate $10,000 Small Model bonus for best Gemma E2B/E4B submission, which stays eligible for the Paper Track. (MAIN rules; MAIN/discussion/751104)
- Baseline/starter notebooks: `sample_submission/` in the data (above). Public starter/top notebooks list: NOT VERIFIED (search_notebooks Unauthenticated). A small-model leaderboard notebook exists: https://www.kaggle.com/code/ryanholbrook/gemma-4-developer-agent-small-model-leaderboard (from MAIN/discussion/751104).
- Leaderboard (third-party snapshot, NOT official API): per Harshit Kumar, 2026-11-10, 5,250 teams: top 0.29 (1 team), 0.24 (11), 0.22 (74), 0.20 (416), 0.17 (964), 0.15 (764); median 0.15. Public split = 58 tasks (1 task = 0.017). Re-running a public 0.24 bundle unchanged gave 0.17; run-to-run sd roughly 1.5-3 tasks. (MAIN/discussion/757588). Team count from API metadata: 5,421.

## 4. Must the paper use Gemma 4?

- No explicit rule requires it. PAPER description: "Submissions can include any related research, as long as it is unpublished." PAPER Evaluation: eligibility requires a Writeup "that documents your research to advance the state-of-the-art for agentic software engineering." Relevance criterion is about "software engineering and agentic learning." Topic list is Gemma-agnostic (tuning, code graph comprehension, tasks/benchmarks, graph reasoning).
- Evidence of tolerance: host OK'd a submission using external dataset (Loc-Bench) with a local Gemma reranker (751804, though that still uses Gemma) and "Prior github repo ... eligible". No staff statement found either requiring Gemma or explicitly allowing non-Gemma-only work: NOT VERIFIED. Safer: include at least a Gemma 4 experiment arm; the track title, welcome post ("leveraging Gemma 4, DiffusionGemma, or code graphs") and framing favour it.
- Must you join the paper competition? Yes: "you must join this competition and submit a Writeup" (PAPER Evaluation). Main-competition participation not required.

## 5. Decision-relevant takeaways

1. 3,000 words count title, abstract, body, captions and tables; exclude references and figures. No official counter, so leave margin (aim ~2,800).
2. Submit early; ensure state is "Submitted" before 2026-11-12 23:59 UTC; resubmit-timestamp rule unclear, ties judged by multiple judges, tie-break "likely original submission time".
3. Code is optional; public GitHub is accepted for code; derived labels, regenerated graphs and traces (with upstream licence cited, no problem statements/test patches) are OK; do not redistribute Competition Data verbatim.
4. Judging likely reads code but may not run it; provide a fast "run all".
5. Evaluation is 5 equal criteria; crowded area is AST/graph localization + self-correction; negative/noise-aware results and rigorous stats exist but are visible in few entries.
